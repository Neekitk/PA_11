# Анализ требований и первичное проектирование структуры репозитория

## 1. Описание уровня и целей интеграции

В рамках мини-проекта **«Система агрегации и интеграции данных интернет-магазина»** предусматривается интеграция внутренней учетной системы торгового предприятия с внешней торговой платформой — маркетплейсом или интернет-магазином.

Основной целью интеграции является автоматизация обмена данными между информационными системами. Разрабатываемый программный модуль должен обеспечивать синхронизацию каталога товаров, автоматическое обновление информации об остатках, передачу статусов заказов и обмен данными с внешней торговой платформой в режиме, близком к реальному времени.

В проекте используются несколько уровней интеграции:

* **Уровень данных** — обеспечивает обмен информацией с базой данных учетной системы, а также импорт и экспорт структурированных файлов. Для передачи каталогов и другой информации используются форматы JSON, XML и CSV.
* **Уровень интерфейсов (API)** — обеспечивает взаимодействие с внешней торговой платформой посредством REST API. Обмен данными выполняется через протокол HTTPS.
* **Уровень бизнес-логики** — отвечает за обработку и проверку получаемых данных, валидацию входящих заказов, расчет актуальных остатков и подготовку данных для передачи между системами.

Интеграционный модуль выступает связующим звеном между внутренней учетной системой и внешней торговой платформой. Это позволяет уменьшить количество ручных операций и повысить актуальность информации о товарах и заказах.

## 2. Перечень ключевых источников и приемников данных

В процессе работы системы данные поступают из нескольких источников и передаются различным приемникам.

### Источники данных

**1. Файл выгрузки складской системы**

Содержит информацию об остатках товаров и их ценах. Файл используется для регулярного обновления данных во внешней торговой платформе.

**2. Входящие вебхуки от интернет-магазина**

Используются для уведомления интеграционного модуля о появлении новых заказов. Полученные данные проходят проверку и затем передаются во внутреннюю учетную систему.

### Приемники данных

**1. База данных учетной системы**

Используется для сохранения информации о новых заказах, полученных от интернет-магазина.

**2. Удаленный сервер маркетплейса**

Получает обновленные сведения об остатках товаров и трек-номера отправлений через REST API.

### Протоколы и форматы обмена

| Направление обмена             | Протокол   | Формат данных |
| ------------------------------ | ---------- | ------------- |
| Взаимодействие с REST API      | HTTPS      | JSON          |
| Передача пакетных файлов       | SFTP       | CSV/XML       |
| Импорт каталога                | —          | JSON/XML      |
| Передача данных о товарах      | HTTPS/SFTP | JSON/CSV/XML  |
| Получение информации о заказах | HTTPS      | JSON          |

Обработка данных осуществляется бизнес-логикой интеграционного модуля. Перед сохранением или отправкой информация проверяется на корректность и соответствие установленным требованиям.

## 3. Структура репозитория проекта

Планируемая структура репозитория проекта:

```text
InternetShopIntegration/
│
├── src/
│   ├── Models/
│   ├── Integrations/
│   ├── Services/
│   └── Program.cs
│
├── config/
│   ├── appsettings.json
│   ├── api-settings.json
│   └── import-settings.json
│
├── tests/
│   ├── UnitTests/
│   └── IntegrationTests/
│
├── docs/
│   ├── architecture/
│   ├── diagrams/
│   └── README.md
│
└── README.md
```

### Назначение основных каталогов

* **`src/`** — основной каталог с исходным кодом проекта. Здесь размещаются компоненты интеграционного модуля и бизнес-логика.

  * **`Models/`** — модели данных, используемые приложением: товары, заказы, остатки и статусы доставки.
  * **`Integrations/`** — классы для взаимодействия с внешними системами через REST API и другими способами обмена данными.
  * **`Services/`** — бизнес-логика приложения: обработка заказов, проверка данных, расчет остатков и организация обмена между компонентами.
  * **`Program.cs`** — точка входа в приложение и запуск основных компонентов интеграционного модуля.

* **`config/`** — каталог конфигурационных файлов. В нем хранятся параметры подключения к внешним API, настройки путей к файлам, параметры импорта и фильтры разрешенных файлов.

* **`tests/`** — каталог автоматизированных тестов. В нем размещаются сценарии проверки отдельных компонентов и интеграционного взаимодействия между системами.

  * **`UnitTests/`** — тестирование отдельных методов и компонентов.
  * **`IntegrationTests/`** — проверка взаимодействия интеграционного модуля с внешними и внутренними системами.

* **`docs/`** — каталог технической и проектной документации. Здесь размещаются описание архитектуры, схемы взаимодействия компонентов, диаграммы и другие материалы проекта.

* **`README.md`** — основной файл с кратким описанием проекта, его назначения, структуры репозитория и инструкцией по запуску.
